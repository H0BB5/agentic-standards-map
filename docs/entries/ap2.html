Agent Payments Protocol (AP2)

Industryspecificationcore entry

Verified 2026-10-14. Status as of 2026-10-13. All entries.

Seams: S4

Status

Open protocol in the GitHub organisation google-agentic-commerce (Apache-2.0); latest release v0.2.0 of 2026-04-28, which "focuses on providing Human Not Present flows"; core specification donated to FIDO.

Relevance

AP2 is available as an extension for A2A and for UCP; its objects are mandates, signed Verifiable Digital Credentials, and the FIDO blog of 2026-05-26 names "Checkout Mandate: This captures the details about and conditions on what the user wants to buy." and "Payment Mandate : This captures the details about and conditions on how the user wants to pay (amount, instrument, timing)." The docs say the Checkout Mandate is shared with the merchant, so the seller is a recipient of the user's signed purchase terms.

The record the other way, the Mandate Receipt that the Verifier signs, is described with a result field in docs/ap2/agent_authorization.md and with a status field in the normative schemas, at the same commit e1ea56d (see issue #374 in the open proposals). UCP's AP2 mandates extension has businesses embed a signature over the checkout terms.

Boundary

The docs index (docs/index.md at commit e1ea56d, the head of main on 2026-10-13) says the initial version supports pull payment methods such as credit and debit cards and that the roadmap includes e-wallets, push payments such as real-time bank transfers, and digital currencies; the text still speaks of an initial version although the latest release is v0.2.0 (2026-04-28).

Owner / governance
Organisation google-agentic-commerce, Apache-2.0; core specification donated to FIDO (repository); FIDO Payments TWG to develop it
Version and state
v0.2.0 (2026-04-28), v0.1.0 (2025-09-16); standardisation continues in FIDO working groups
What it signs
Mandates (signed Verifiable Digital Credentials): Checkout Mandate (shared with merchant), Payment Mandate (instrument, amount)
Who signs
Closed mandates: the User (Human Present) or an Agent key (Human Not Present), whose trust "is provided by open Mandates that are signed by the User or a trust list of Agent Providers"; the Merchant provides "a merchant-signed JWT containing the Checkout" (docs/ap2/specification.md, Modes and Checkout Mandate, commit e1ea56d, 2026-10-05); FAQ: "user-signed Checkout Mandate"
Receipt or record
Checkout Receipt, returned by the Merchant after accepting or rejecting the Checkout Mandate, with fields status (Success or Error), iss, iat, reference (hash of the closed Mandate) and order_id on Success (checkout_receipt.json); a Mandate Receipt is "a Verifier-signed JWT" (agent_authorization.md); a "signed Payment Receipt" is returned by the Merchant Payment Processor (specification.md); all at commit e1ea56d, 2026-10-05; chained mandates give a verifiable audit trail (docs/index.md)
Dispute
FAQ: in a dispute the network adjudicator can use the user-signed Checkout Mandate; dispute process: not found in docs, 2026-10-03
